## 一、沸点（三选一）

### A · 反差数据型（推荐首发）

552B 的大模型，反而把显存吃下来了。

DeepSeek V4.1 Flash 是 552B MoE——比不少 Pro 型号还大——却把百万 token 的全局 KV Cache 压到 **890 字节/token**，约为上一代 V4-Flash 的四分之一，1M 上下文只占 **0.89 GB**。消费级显卡能塞下。

反直觉的地方在于：它的秘密不是"把模型做小"。CED 把 KV 的"生成"和"消费"解耦了——解码器不再逐层重算 KV，只读不写。prefill 算力实测砍半（2.000x）。

不是模型变小了，是账本换了算法。

### B · 现象共鸣型

跑到 200K 上下文，先爆的不是模型，是显存。

你的 HBM 占用曲线比工资涨得还快。KV Cache 把**存储、带宽、算力**三项成本同时放大——每层都存一份、每步都读一遍、每个 token 都算一次。长上下文真正贵的从来不是"模型不够聪明"，是这三重放大。

V4.1 Flash 用四个机制把这个乘子拆掉：CED 前移 KV 生成、FP4 砍精度、CSA2 跨层复用、SWA 有界重放。百万 token 的全局 KV 从"装不下"变"塞得进"。

这篇把四个机制逐个拆开，配 5 张架构图 + 2 段能跑的脚本，并说清哪里不能全信。

### C · 认知反差型

别被"FP4 量化"骗了。

裸 4bit 确实接近 4x 压缩，但**没有 scale 的 4bit 在注意力里会直接崩精度**。V4.1 用"每 16 个通道配 1 个 E4M3 scale"的代价，把 4x 降到 **3.56x**，换来的是可用。剩下的缺口靠 CSA2 跨层复用 + SWA 有界重放的结构性压缩（1.125x）补上。

工程是权衡，不是免费午餐。890 bytes/token 这个数字背后，是"精度 3.56x × 结构 1.125x ≈ 4.0x"的量级分解，不是一句"上了 FP4 就 4 倍"。

## 二、评论区首评（自己发，引导讨论）

**首评（选一条发）**

> 补一个最容易读反的点：V4.1 Flash 不是"更小"，是 KV 的**生成和消费解耦了**。
>
> CED 架构下，编码器对 N 个输入 token 跑 20 层，末层隐状态经各解码层专有的线性投影**一次性映射**出全局 KV；解码器只对自己新生成的 n 个 token 跑 20 层，只读这份全局 KV、不再逐层重算。prefill 复杂度从 O(N·L) 变成 O(N·L/2 + n·L/2)，脚本实测长上下文提速 2.000x。
>
> 很多人把 CED 理解成"参数更少"，恰恰相反——552B 比不少 Pro 还大。它改的是信息流动方式，不是模型规模。这条想清楚，后面 FP4 / CSA2 / SWA 三件事就都顺了：它们打的是同一个根，KV 的「存储 × 带宽 × 算力」三重放大。

**备选首评（偏脚本 + 踩坑）**

> 文末放了两段能直接跑的脚本，对应两个最容易被讲空的地方：
>
> 01 是 **KV Cache 字节算术与压缩比复现**——把 FP4(E2M1) 分组量化的元素字节算清楚：`(16×4bit + 1×8bit scale) / 16 = 0.5625 B/值`，精度压缩 3.56x；再复现报告口径的 890 B/token ≈ V4-Flash 的 1/4、相对 V1 的 437x、1M token 的 0.89 GB。`--self-test` 强制断言这些数值，可挂 CI。
>
> 02 是 **CED prefill 复杂度对比**——把"层数减半"的算力账算清楚：N=1e6、n=1 时传统 40,000,000 vs CED 20,000,020，提速 2.000x。改 `L_ENC`/`L_DEC` 就能测其他 CED 配比。
>
> 最该警惕的是**持久化恢复边界**：报告自己写明 cache-resumption 仍需更多压力测试。1/8 持久化体积在常规负载成立，长程依赖、超高并发恢复、异常断点这些边界，官方没盖章，生产别照单全收。

## 四、本篇做了什么 / 对哪些群体有用

### 本篇做了什么

- 把"**为什么 V4.1 Flash 能把全局 KV 压到 890 bytes/token**"当故障拆：先锁总症状，再找四个"本该让 KV 变小的机制"，逐个验证贡献，最后看四项怎么叠加到 890。总根 = 长上下文推理的成本瓶颈 = KV 的「存储 × 带宽 × 算力」三重放大。
- **机制 1 CED（打存储+算力）**：40 层 = 20 层因果编码器 + 20 层解码器；解码器全局 KV 由编码器末层隐状态经各解码层专有线性投影**一次性映射**生成，不逐层重算。prefill 从 O(N·L) → **O(N·L/2 + n·L/2)**，脚本实测 **2.000x**。
- **机制 2 FP4(E2M1) 分组量化（打存储）**：每 16 通道配 1 个 E4M3 scale，`(16×4bit + 1×8bit)/16 = 0.5625 B/值`，精度压缩 **3.56x**；Decode 时在寄存器级反量化回 FP8 使用，权重路径不经它。
- **机制 3 CSA2 跨层复用（打算力+存储）**：Full 层对所有因果可见位置打分、按最大索引分选 block，建**共享候选池**（2048 block × 8 位置 = 16384）；Reindex 层只池内取 Top-512；主 KV 与索引器 K 跨层共享。
- **机制 4 SWA 有界重放（打存储）**：持久化前缀剔除 SWA 局部 KV，恢复时仅回放尾部 128 token 近似重建（理论精确重放长度 2560）；持久化 KV 约占 V4-Flash 的 **1/8**。
- **收束**：四项打不同乘子，叠加 **≈4.0x**（精度 3.56x × 结构 1.125x，量级分解、非精确乘法）；报告口径 890 / 3560 / 437x / 0.89 GB / V1 388930 B·token⁻¹。
- 引**一手源**（HF 权重 + 技术报告 PDF + 官方中英公告）+ 交叉核实（机器之心 / Baseten），未编造。
- 给 **2 段纯标准库脚本**（KV 字节算术 / CED prefill 复杂度，均带 `--self-test` 自检，已移出到 GitHub）+ 列 **9 坑自检清单**（按症状归类）。

### 明确不承诺什么（评论区如遇质疑可直接引用）

- **不背书基准分数**：890 bytes/token 与基准（GPQA 90.9 / HLE 36.8 / Terminal-Bench 2.1 90.6 等）是 DeepSeek **自测口径**，第三方评测待补。正文「本文不承诺什么」一节已注明。
- **不声称反向还原了架构**：逐层维度（head 数、head_dim）未公开，脚本用报告落地值做**算术复现**，不是逆向工程。
- **cache-resumption 边界未盖章**：报告明确"需更多压力测试"，1/8 持久化体积在常规负载成立，长程依赖 / 超高并发恢复 / 异常断点请自建压测。
- **不做"省 90%"式夸大承诺**：FP4 非免费午餐，实测精度 3.56x + 结构 1.125x，量级到 4.0x，仅此而已；`3.56 × 1.125` 是量级分解而非精确乘法。
