## 一、沸点（三选一）

### A · 反差数据型（推荐首发）

全量上下文在 LOCOMO 基准上准确率 72.9%，是所有记忆方案里最高的。

代价：每条对话 26,000 token，p95 17.12 秒。

记忆系统的价值从来不是"让 AI 更准"，是让它便宜到能上线 —— 用 6 个百分点的准确率，换 14 倍的 token 和一个数量级的延迟。

但这笔交换有个前提：你换来的那点损失，不能落在"知识更新"和"时序推理"上。这两类才是记忆存在的理由，也是最容易失守的两类。

用 `--k 1` 跑一次分层评测，你会发现总分 100% 的系统，在这两类上可能是 0%。

### B · 场景痛点型

周五下班前跟 Claude Code 花了两小时定下来：订单服务不用分布式事务，改本地消息表 + 补偿任务。

周一新开会话让它补完，它给了我一个 Seata TCC 方案。

它没忘 —— 它根本没有"上周"这个概念。那两小时的讨论，对它来说从来就不存在过。

上下文窗口不是短期记忆，它是每次请求重建的工作区。你发的每一条请求，KV cache 都要重新算一次。

所以"记忆"真正难的不是存哪儿，是一条事实从写入、更新、作废到被读回的整条生命周期。

### C · 反直觉安全型

给记忆系统加了 LLM-as-a-Judge、ProtectAI、PromptGuard 三道过滤器之后，记忆投毒的条件攻击成功率还留在 75%–77%。

换成困惑度过滤能完全阻断检索，代价是同时误杀 71.8% 的正常内容。

这就是安全与效用的真实边界：一个靠"拒绝大部分记忆"来防御的系统，已经把记忆系统的价值一起拒掉了。

2026 年这块的论文密度突然上来了：MemGhost 一封邮件写入假记忆并隐藏这次写入，后台模式成功率 87.5%；InjecMEM 单次交互就能持久化植入。OWASP 已经给了编号 ASI06。

## 四、本篇做了什么 / 对哪些群体有用

### 本篇做了什么

- 把"AI 失忆"这个症状拆成三个可独立治理的失败模式（**记不住 / 记错了 / 记了也白记**），指出共享总根：把记忆当存储问题，而不是一条事实的完整生命周期问题。
- 讲清了上下文窗口为什么天生不是记忆（每请求重建的 KV cache），以及全量上下文这条路为什么走不远（26,000 token / p95 17.12s，来自 Mem0 在 LOCOMO 上的基线数据）。
- 给出记忆的**四层划分**与各自失效模式、**双路径写入架构**（热路径管当下、冷路径异步抽取），以及"最值钱的记忆是被否决的路径"这个判断。
- 用**双时间戳**解释过期问题，用 MemGhost / InjecMEM 两篇 2026 年论文给出投毒的量化现实，并指出过滤器为什么基本无效。
- 把市面方案归成**四个流派**（抽取式 / 时序图 / OS 分层 / 文件系统），给了一条按"时间 / 多跳 / 规模 / 跨工具"排序的选型决策路径，并用 Letta 的反直觉数据点说明架构比工具重要。
- 三个可上仪表盘的指标，9 个按症状归位的坑，以及 3 个可运行的自检脚本。

### 对哪些群体有用

| 群体 | 能拿走什么 |
|---|---|
| 每天用 Claude Code / Cursor / Codex 的人 | "记否决路径"这一条 + 分层评测脚本，当天就能用 |
| 在做 agent / 助手 / 客服的工程师 | 四层划分、双路径架构、四流派选型，直接决定技术选型 |
| 做 agent 安全的 | 带论文编号的威胁模型 + 过滤器为什么不够的真实边界 |
| 架构师 / Tech Lead | 三层治理（写入 / 存储 / 检索）+ 记忆写入审计的最低要求 |

### 明确不承诺什么（评论区如遇质疑可直接引用）

- **不推荐某个框架最好**。四流派各有适用面，文中数据来自各自论文与厂商公布，LOCOMO / LongMemEval / DMR 是三个不同基准，口径不完全一致。
- **不承诺上了记忆系统就一定更好**。全量上下文在 LOCOMO 上的准确率（72.9%）仍高于所有记忆方案，记忆是成本/延迟与准确率之间的交换。
- **MemPalace 自报的 LongMemEval R@5 96.6% 需打折看**：是 R@5 而非准确率，且该项目维护者曾公开撤回过自己早先的部分基准声明。文中只作"文件系统流派能做到什么程度"的参考。
- **Letta 74.0% 的对比**来自 Letta 团队公布，不是同一论文内的统一评测。
