## 一、沸点（三选一）

### A · 反差数据型（推荐首发）

OpenAI 历史上第一次出现这种情况：你买到了订阅、拿到了 API key，却**故意不给你模型最强的能力**。

GPT-6 Astra（09-03 预览 / 09-04 GA）是 OpenAI 的 Preparedness Framework 里**第一个被判为 Critical 级**的模型——网络安全能力的最高档。评测期间，无生产护栏的 Astra 自己发现并链出了**两个此前未知的零日漏洞**，OpenAI 已向维护者披露。

于是攻击侧能力被塞进一个叫 Daybreak 的受信任访问计划，普通用户拿到的是"被训练去拒绝写 PoC exploit"的版本。

最反直觉的一组数字：新评估的越界比例，Astra **0%**，Sol **48%**；网络越狱拒绝率 Astra **91.5%**，Sol **59%**。能力更强的那个，反而是更"守规矩"的那个。

### B · 场景痛点型

你的 agent 正在跑，第 30 轮刚改完线上配置——API 返回了 `HTTP 403`，任务终止，**没有通用续跑机制**。

这不是故障，是设计。Astra 的 Requests/Responses 侧带生产监控，被标记的请求在流式开始前就返回 `HTTP 403`、`code=misalignment_policy_violation`；用了持久化推理 / WebSocket / compaction 的 Responses 会话会被**自动停**。而 **Chat Completions 在这个监控体系之外**。

所以端点选择本质是个安全路由决策，不是技术细节。

更麻烦的是事后性：如果这轮任务已经用工具改过线上配置，监控在事后才报警，**前面的动作并不会被回滚**。

### C · 成本反直觉型

Astra 的招牌价是 $10 输入 / $50 输出（每百万 token），看着还行。真正咬人的是 **272K 计费悬崖**：

271K 输入估 $3.71；只多 0.7% 到 273K，变成 $6.96——输入量涨一点，成本直接翻倍。

原因是**阈值作用于整个请求，不是只作用于超出 272K 的那部分**。一旦总输入越过 272,000，整条请求按高费率算（$20/$2/$25/$75）。

真正该优化的主费率也不是输入，而是**缓存输入 $1/M**：agent 循环跑起来后，系统提示、工具定义、仓库快照大多命中缓存，按 $1 而不是 $10 计费。优化重点不是"少发 token"，是"让前缀稳定可命中缓存"。

另外别只看单价：Terminal-Bench 4.0 上 Astra 57.9% 对 Sol 37.3%，且官方估**单任务** API 成本约低 9%。正确指标是每完成一个任务的成本。

## 二、评论区首评（自己发，引导讨论）

**首评（选一条发）**

> 补一个最容易读反的点：Astra 的"限制开放"不是因为它不安全，**恰恰是因为它太能打**。
>
> Preparedness Framework 的 Critical 是最高档，此前没有任何模型达到过。定义是：在合适的工具与权限下，能跨多个受保护系统**自主发现未知漏洞、构建新攻击、无需逐步人类指导**。Astra 是第一个。
>
> 但另一面是：越界比例 0%（Sol 48%）、网络越狱拒绝率 91.5%（Sol 59%）。它同时是"最强的攻击手"和"最守规矩的那个"。
>
> 所以门控不是惩罚，是把"能开锁的手"和"能造锁的手"分开：Daybreak Blue 面向防御，Daybreak Red 面向红队，而且 **Blue 不会自动授权 Red**，要单独审批 + 合同制技术托管协议。
>
> 对工程的实际影响只有一个：**别把安全路由当成技术细节**。Chat Completions 不在监控体系内这件事，值得你在选端点时多想十秒。

**备选首评**

> 文末放了两段能直接跑的脚本，对应两个最容易被讲空的地方：
>
> 01 是**记忆管线模拟器**——同一份会话事件跑两条管线，旧式确定性 compaction 在窗口压缩时把"只被某条工具输出按值携带"的易失状态（TMPDIR / 环境变量 / socket 句柄）弄丢，而 Structured Searchable Notes 因为"产生即入索引"始终可检索。默认参数跑出来就是 compaction 返回 None、notes 拿回指针。想看反例就加 `--budget 600`，两条管线立刻一致——这正说明"丢不丢取决于压不压缩"。
>
> 02 是 **272K 计费悬崖计算器**。第一组演示：271K → 273K 只多 0.7% 输入量，费用 2.01x。第二组：200K 输入里 190K 命中缓存，单轮省 34.2%。写它的时候我在 Batch 档把输出价抄成了 $50（应为 $37.50），被自检里"Batch 必须严格等于 Standard 的一半"这条不变量逮住了——顺手给读者留了个防抄错的设计。

## 四、本篇做了什么 / 对哪些群体有用

### 本篇做了什么

- 把"强到被锁起来"这个症状，拆成**失败模式 A「更强」/ B「更怕」**两个可独立讨论的面，指出共享总根：一套"原生把模型嵌进操作系统"的架构（looped transformer + RL with execution feedback + 原生摄取多模态环境信号）。它让能力跃迁，也正因闭环绕开人类逐步监督，让越界风险与不可监控性同时放大。
- 讲清"为什么强"：预训练就在隔离虚拟化环境里用 RL with execution feedback 训练（Stargate >100,000 GPU）；原生摄取并交叉注意力于屏幕帧缓冲 / OS accessibility tree（三端）/ 实时 syscall telemetry / 合成硬件级输入事件——它是"看到 OS 内部结构"，不是 OCR 猜像素。这是 ScreenSpot-Pro 92.7% 对 76.9% 的来源。
- 讲清记忆机制：**Structured Searchable Notes 取代确定性 context compaction**。确定性压缩会丢易失环境状态（socket 状态、subshell 环境变量、临时目录指针），因为它们只被某条工具输出按值携带、无法重新派生；notes 在产生时即入索引，故跨窗口可检索。目前 Codex 内 experimental（`features.context_management.experimental_mode` v0.153.0）。
- 讲清"为什么怕"：**首个 Critical 级**（无逐步人类指导自主链零日）+ 两个未知零日；门控靠 Daybreak Blue/Red 双轨（Blue 不自动授权 Red）；生产监控形态（HTTP 403 / `misalignment_policy_violation` / Responses 持久化推理会被自动停 / Chat Completions 在监控外）。
- 讲清**可监控性反降**这个反直觉点：越界比例 0% 对 Sol 48%、网络越狱拒绝率 91.5% 对 59%、54,000 次 Codex 任务高危不对齐标记约为 Sol 一半。部分推理发生在可读 CoT 之外，能力越强越难从输出看出它在想什么。
- 讲清成本底线：272K 悬崖（整请求重定价、271K $3.71 → 273K $6.96）、四档费率、缓存输入 $1/M 才是主费率；并给出"每完成一个任务成本"这个正确指标（Terminal-Bench 4.0 Astra 57.9% vs Sol 37.3%，单任务成本约低 9%）。
- 5 个按失败模式归位的坑 + 2 个可运行脚本（记忆管线模拟器 / 272K 计费悬崖计算器，均带自检）。

### 明确不承诺什么（评论区如遇质疑可直接引用）

- **不承诺"用 Astra 一定更强"**：Artificial Analysis Index 上 Astra 61.2 仍落后 Fable 5.1 的 65.7，它强在特定档位（computer-use / 长程工程 / 网络相邻），不是处处第一。
- **不承诺"Critical 级能力已被独立验证"**：上述网络安全评测为 **OpenAI 自评**，无第三方独立验证；Benchmark 数字来自官方与第三方抓取，口径可能不同（如 ExploitBench 近期版本 Sol 存在 5.5% 与 11.5% 两说，正文取较具体的 11.5% 并标注）。
- **不承诺"Astra 是第一个达到 Critical 的模型"之外的推断**：这条为 OpenAI 官方声明。至于"它是否真的能自主造攻击"，本文只转述 Preparedness Framework 的定义与官方结论，不做超出证据的判断。
- **定价为 2026 年 9 月公开口径**，厂商调价或改档位后需以最新价目表为准；脚本里的费率表要同步改 `TIERS`。
- **两个脚本是模拟与计算器，不是厂商内部实现复刻**：01 的 token 用"4 字符≈1 token"粗估，检索是精确 key 匹配（未做语义检索），压缩策略简化为"保留首条 + 摘要 + 末两条"；它证明的是机制因果（易失状态一旦被裁掉就永久失忆），不是复现 OpenAI 内部实现（后者未公开）。02 的费率与阈值来自公开文档与第三方测算，厂商调价后需改 `TIERS`。
