# code/后西游记AIGC长剧

两款**纯标准库、可直接运行**的脚本，对应正文的两个失败模式治理：

| 脚本 | 对应正文 | 作用 |
|---|---|---|
| `01-consistency-eval.py` | 问题 2 / 坑 7 / 三层治理·一致性层 | 表演级情绪连续性门禁：相邻定帧情绪向量跳变过大判「情绪断层（微表情僵硬）」，另有"实际弧线 vs 剧本期望弧线"模式定位最僵帧 |
| `02-cost-estimator.py` | 问题 4 / 坑 3 / 三层治理·编排层 | 资产复用率驱动边际成本模型：复用率越高单集成本越低，验证"资产生息"曲线；含单集预算门禁 |

## 运行

```bash
# 脚本1：表演级情绪连续性门禁（内置示例，演示一处僵硬帧拖垮整段文戏）
python3 01-consistency-eval.py --self-test

# 脚本1：仅跑相邻跳变门禁
python3 01-consistency-eval.py --scene examples/frames.jsonl --max-jump 0.35

# 脚本1：实际情绪弧线 vs 剧本期望弧线，定位最僵帧
python3 01-consistency-eval.py --scene examples/frames.jsonl --arc examples/ref.json

# 脚本2：资产复用率→单集成本（多复用率对比，验证边际成本递减）
python3 02-cost-estimator.py --self-test

# 脚本2：低复用率触发预算门禁（复用率 30% > 成本失控）
python3 02-cost-estimator.py --reuse-rate 0.30 --budget 100
```

## 已知边界

- 脚本1 的 `examples/` 情绪向量是**手工构造的模拟向量**，仅演示评估口径。真实产线把 `emotion` 换成表情/表演分析模型（如面部动作单元 AU 序列、微表情识别）输出的 embedding 即可。
- 脚本2 的 `c0 / overhead / discount` 为《后西游记》公开口径（单集 90 万、109 角色/143 场景资产跨集复用）的近似拟合参数，用于演示"复用率→成本"的递减关系；真实落地以剧组实际账本为准。未含音频/合规/宣发。
- 阈值 0.35（相邻跳变）、10%（断裂间隙占比）、门禁 100 万（单集预算）均为经验起点，按文戏宽容度与预算调。

## 与正文的映射

- 坑 7（物理/情绪异常不修）→ 脚本1 门禁：相邻定帧情绪跳变超阈值即判微表情僵硬，合格帧率不达标不许进剪辑。
- 坑 3（抽卡无门禁 / 复用率不足）→ 脚本2 预算门禁；示例 `reuse-rate 0.30` 即对应"资产不沉淀、复用率低、成本失控"的翻车面。
- 问题 4（资产生息）→ 脚本2 多复用率对比：复用率每升一档单集成本持续下降，正是《后西游记》单集 90 万（约传统 1/10）的成因。
